# An instance is its Worker secrets; the tracked configuration names no tenant

Nudge is a self-hosted template (plan decision A12) whose consumers pin the upstream actions by commit hash and keep pulling upstream to match action versions to their Worker (`docs/adr/0003`), so a fork must never have to edit a tracked file. Every instance value is therefore a Worker secret, sensitive or not — the owner allowlist, the Discord public key, bot token, channel id and allowed user ids, the GitHub App id and private key, the optional audience — loaded in one command (`bunx wrangler secret bulk .dev.vars`) from the gitignored `.dev.vars`, whose template `.dev.vars.example` is committed; the custom domain is attached once outside the tracked file (`wrangler deploy --domain <hostname>`, or the dashboard's Domains & Routes); `wrangler.toml` has no `[vars]` and no `routes`, and no KV binding, because request state lives in the Discord message (plan decision A21). Secrets are the one store that survives every deploy and is identical for CI and by-hand deploys; the cost is that values are write-only afterwards, so the local file is the readable copy. Rejected: plain values as dashboard variables under `keep_vars` (two places to set, no bulk import); GitHub repository variables passed with `--var` by the deploy workflow (a by-hand deploy pushes a config without them and wipes what CI set); values in the tracked `wrangler.toml` (every upstream pull conflicts on the one file the fork had to edit, which is what Milestone 2 was drifting into).

Source: user decisions A22 and A23, grill-me session 2026-09-26 (`docs/plans/EXECPLAN_NUDGE.md` § Decision Log), amending the values half of A13. That wrangler publishes only the routes and custom domains listed in its config was read from wrangler 4.136's deploy code (`publishRoutes`, `publishCustomDomains` run only for configured entries), not yet confirmed on the live Worker; the confirmation is a step of Milestone 2's first pull request.
